# Bot AI for Warcraft Legacies

Computer-player bots for **Warcraft Legacies 4.8.2** (the version that still has the Old Gods). The bots capture
control points, fight, produce, research, follow faction quests and lore events (Legion summon, Ragnaros, ...).
Current version: see `AiSetup.Build` in `AiSystem.cs`, the `-version` chat command and `CHANGELOG.md`.

Documents in this folder: `README.md` (this file: use, commands, how the bots move, what was already tried),
`TODO.md` (the plan in phases and open work), `CONCEPTS.md` (designs), `CHANGELOG.md` (every version),
`MEASUREMENTS.md` (numbers per game), `WORKAROUNDS.md` (what the bot needs outside `Ai/`), `ROUTES.md` (generated graph
report), `AI_AGENTS_CONTEXT.md` (handover for AI assistants: rules, facts). These describe the bot only; the map it is
developed in (a fork) documents itself in its own folder.

## Installing into a WL fork

1. Copy this `Ai/` folder to `src/WarcraftLegacies.Source/Ai/`.
2. Add one line to `src/WarcraftLegacies.Source/Setup/GameSetup.cs`, directly after `Artifacts.Setup();`:
   ```csharp
   WarcraftLegacies.Source.Ai.AiSetup.Setup(); // [BOT]
   ```
3. The other hooks and what still ties the bot to the 4.8.2 map are listed in `WORKAROUNDS.md` (bot picks in click
   menus, leaver takeover, the `%` fix in `Loc.cs`).
4. Build as usual. Every computer slot in the lobby becomes a bot.
5. Code outside `Ai/` (a fork's own content) talks to the bot only through `AiApi.cs`; the bot never uses such code.

## Before you publish a build: the command switch

At the top of `AiDebug.cs`:

```csharp
public const CommandAccess Access = CommandAccess.Everyone;
```

| Setting | Effect |
|---|---|
| `Off` | **Release.** No AI chat command at all. `-autopilot` still works, but fair (see below). |
| `HostOnly` | Read-only commands for everyone; game-changing commands only for the host (lowest human slot). |
| `Everyone` | Every command for every player. **Testing only.** |

Heavy commands (`-debug1..4`, `-edges`, `-ids`, `-autodump`, `-tp`) only work when a single human is in the game.

## Playing with bots

- **Bot strength vote** 49 s into the game (0.43.1 scale): Recruit (bots lose ~50 gold/min), Soldier (lose ~25),
  Veteran (no bonus gold), Commander (+~50), Warlord (+~100, the old Veteran; may lag). Majority wins; ties go toward
  Veteran; no votes = Veteran. Bots still get free techs, heroes and revives.
- `-autopilot` hands your faction to the AI; type it again to take over. All players are told.
  - **Fair** (release build, `Access = Off`): the AI plays with your own resources — no bot bonuses, 60 s cooldown.
  - **Test** (`HostOnly`/`Everyone`): full bot treatment (gold subsidy, free techs, revives, missions, waves).
- Bots get bonuses humans don't: gold subsidy, free techs, upgrades and heroes, free hero revives, starter production
  buildings, scripted missions (Ragnaros, hero visits, kill targets, area clears).

## How the bots move (0.51 -- end of phase 1)

One bot is serviced every 0.5 s (round-robin: with 16 bots each one every ~8 s); all periodic work runs in one
scheduler with 0.25-s slots (`AiScheduler`). Per service, in this order:

1. **Army pass** (`SimpleBot.Process`): every orderable army unit of the bot -- not on a mission (`AiState.MissionUnits`),
   not at sea (`AiFerries.InTransit`), not a ferry boat. Guard positions are removed once per unit (`AiGuard`, 0.48.4:
   without that, units out of orders walk back to where they were trained). Measurement samples (`AiTrack`).
2. **Theatres** (`AiTheatres`, 0.47): the units are split by walking component (a continent, an island group); up to
   3 fronts per bot, each with its own state slot (`S(pid)`), target, staging, attack group and defence. The main
   front moves only after ~30 s of empty plans or a 60-s "twice the food" hold.
3. **Graph** (`AiRoutes.g.cs`, generated by `tools/shattered-legacies/ai/gen_routes.py` from map data only): nodes = CPs + area nodes,
   walking edges, a 256-unit region map. Live: rock edges closed while WL's rocks stand (15 s); portal edges every
   30 s -- every active waygate (owner-only for WL's tram / Legion teleporters / exterior Demon Portal), the bot's
   hidden portals (Tomb <-> Argus, Old Gods rift) and the ferry piers.
4. **Defence first** (`AiDefense`): an attacked own CP on the army's landmass within 9000 -> min 30 s, 45-s cooldown;
   a CP far behind the attack group is defended by the rest (0.47).
5. **Target** (`AiRoutes.Pick`): Dijkstra from the bot's own nodes (territory) scores candidates -- CPs (neutral half
   cost, quest CPs on the front 0.3, finish-off 0.5), enemy structures in node areas, leftovers (+2500) and creep camps
   (+3000) scored from the army; plus half the walk from the group ("only forward"). Re-plan when the target is gone or
   every 30 s; switch only for < 0.5 x the score and never to a target farther on foot (commit, 0.48.4). Nothing
   reachable: wait at the nearest closed rock edge of the land, else hold where the army stands. Sleeping creeps at the
   target are woken once the army is there (`AiWake`).
6. **Army split** (`AiArmy`): the attack group = the units nearest to the target until their food covers the need
   (enemy food x 1.5 + structures x 8, at least 50; everybody at 80 %); the rest waits at the staging point (the last
   own node on the route, kept within 2500). Orders on a target change, else on the 20-s heartbeat only to IDLE units
   away from their point; refill after losses.
7. **Movement chain** (`AiRoutes.Chain`): queued attack-moves along the route (at most 8 points; one backward route tree
   per destination, 4 kept). A portal leg ends at the entry: the unit gets a ticket and the pseudo-portal trigger
   (`AiPortals`) teleports it and gives it the rest of the way. A ferry leg (`AiFerries`, 0.50): the unit boards
   (hidden, paused), the bot's boat sails the lane (`tools/shattered-legacies/ai/gen_lanes.py`) and the units land and continue. Missions
   (hero visits, stranded heroes, Ragnaros) travel the same way (`AiRoutes.MoveVia`).
8. **Production** (separate 1-s task): every building trains from its own list, only below the unit budget
   (`AiBudget`, 30 + 5 food per held CP).

**Portals and passages -- how they open** (each open waygate of a neutral owner is a one-way graph edge, read every
30 s; rocks every 15 s):

| Passage | Opens | Made by |

| Thandol Span rocks (Arathi <-> Dun Modr) | turn 30 (WL removes the rocks) | WL |

Designs of the planned parts: `CONCEPTS.md` 6-9. The engine is the limit: with thousands of units and orders, WC3's
pathfinder queue delays every order (players feel 1-2 s); see `CONCEPTS.md` 9.

**A/B in one game (0.46)**: behaviour switches have the modes `on`, `off`, `ab` and `ab2`. `ab` switches the
feature on for the bots whose player slot has a 0 in the switch's bit, `ab2` for those with a 1 -- guard bit 0, gather
bit 1, spread bit 2, so the halves of different tests are independent. The dump names the slots of each half and
compares them. Next game: `ab2` (swaps the halves; factions differ).

## The dump file

`call Preload( "…" )` wraps every line — send the file as it is. Sections:
**PINNED** (one-off events, `TICK ERROR`/`FAILED` lines — read first), **UNITS** (units per player, orders), **TEAMS** (CPs per team), **TRAINED** (what each bot trained / never trained), **PORTALS**, **LOAD** (units touched per tick,
the multiplayer lag indicator; since 0.40 also the scheduler, orders by distance and one line per periodic task; since
0.41-0.44 the army orders line (change / idle-away / rest / refill / exit, chains, stalled %), switches per bot, bot
income paid), **ROUTES** (0.42+: per bot target / score / front / next node; waygates, creep camps, gather counters),
**BOTS** (target, reason, frontiers, army by landmass, heroes), **WAVES**,
**PERMADEAD**, **EVENT LOG** (last 300 changes), **NODES**, **EDGES**.

## Measuring a game

`python3 tools/shattered-legacies/ai/dump_summary.py <the game's WLAI_*.txt files> --append "<note>"` writes a short summary (units,
orders/min, LOAD, errors at 10/20/30/45 min) to `MEASUREMENTS.md`, so the numbers stay in the repo. Details there.

## Testing a build

1. `-version` shows the map title and the expected bot build. 2. No `SYSTEM ERROR` text in
the first turns. 3. `-autodump` at the start; afterwards PINNED has no `TICK ERROR`/`FAILED` and "portals: 0
pair(s) created (always)" (0.50: no AI waygates any more; LOAD shows "ferries (0.50) on: 8 links"). 4. BOTS: states like `atk`/`cap`/`def`, real army sizes. 5. `-portals` shows all pairs;
after a summon the Demon Portal stands where the ritual was cast. The release-specific checks are in `TODO.md` ("Check in the next playtest").

## Checking which units the bots build

1. Offline, what is possible: `python3 tools/shattered-legacies/ai/unit_scan.py <faction>` -- every unit/hero of the faction, where it
   is trained, and why the AI leaves it out. Classification is exact: buildings by WL's category, ships by their WC3
   naval base type, builders by WL's "Builder" category, researches by `UpgradeData`; "no building of this faction
   trains it" = quest/summon unit. 0.38: 248 trainable, 161 ships, 21 builders, 9 quest/summon units (439 total).
2. In the game: `-dump` -> section TRAINED, per bot "trained types x count" and "never (N): ...". A type in "never"
   that the scan marks OK means: requirement not met yet (often a quest -- the scan names it) or not reached yet.

## If the game freezes
With `-autodump` on, `CustomMapData\WLAI_heartbeat.txt` is rewritten every 10 s (time, units on the map, orders
per minute, last tasks) -- send it with the dumps after a freeze.
So far freezes came only with alt-tabbing on Linux/Proton, picture frozen while sound kept playing -- most likely
the graphics layer, not the map. The steps to tell the two apart are in `TODO.md` ("Freeze check"). A map/script hang
also happens without alt-tabbing and, in multiplayer, freezes every player.

## Developer checks

Python, `pip install tree-sitter tree-sitter-c-sharp lupa --break-system-packages`. The tools are development aids of
the repository that hosts the bot (here `tools/shattered-legacies/ai/`), not part of the bot:

- `python3 tools/shattered-legacies/ai/check_refs.py` — wrong-class/private references, the two CSharp.lua limits (Lua locals per
  class, initialized static fields per class) and the layer rule (LAYER: the bot uses fork code; API: fork code
  bypasses `AiApi`). Checks `Ai/` and the fork's folder. **Run before every build.**
- `python3 tools/shattered-legacies/ai/lua_check.py artifacts/war3map.lua` — compiles the built script with Lua 5.3; catches what
  makes Warcraft III call the map "unavailable or corrupted".
- `python3 tools/shattered-legacies/ai/scope_check.py src/WarcraftLegacies.Source/Ai <other changed .cs files>` — catches C# scope
  errors a syntax check misses (a local hiding a type name, e.g. `timer timer = ...`; a local re-declared in a nested
  block). Not a compiler, but it caught the 0.37.1 build break.
- `python3 tools/shattered-legacies/ai/using_check.py` — extension methods called without their `using` (the publish step's
  CSharp.lua compile fails on them; `dotnet build` of the CLI does not compile the map code). **Run before every build.**
- `python3 tools/shattered-legacies/ai/gen_ai_data.py` — regenerates `AiData.g.cs` (train lists, hero skills ...) from WL's data
  (and the fork's own production data, handed over through `AiApi.AddProductionData`); run after every WL update, then
  rebuild.
- `python3 tools/shattered-legacies/ai/render_map.py [--regions]` — draws terrain, CPs and the route graph to `tools/shattered-legacies/ai/out/route_map.png`
  (for discussing the graph; run after `gen_routes.py`).
- `python3 tools/shattered-legacies/ai/gen_routes.py` — regenerates the route graph `AiRoutes.g.cs` from map data (CPs, pathing,

  those CPs did not exist.
- `python3 tools/shattered-legacies/ai/unit_scan.py [faction|--summary]` — which units/heroes each faction has and whether the AI can
  train them (with the reason / the unlocking quest). Compare with the dump's TRAINED section.
- `python3 tools/shattered-legacies/ai/map_query.py walk X Y` (also `near`, `area`, `find`, `around`, `rect`) — checks coordinates
  against the map's source data (terrain pathing, preplaced units, `Regions.X`) before they go into `AiConfig.cs`.

**CSharp.lua limits to remember:** all static members of a class become locals of one Lua function (limit 200),
and non-private static `readonly` fields are added uncounted; initialized static fields past ~55 per class stay
`nil`. Keep classes small; shared state as `internal static` without `readonly`.

## Known WL 4.8.2 bug fixed with the bot: `%` in quest/power text (`[BOT]` in `Loc.cs`)

`SYSTEM ERROR: … invalid use of '%' in replacement string` (Kul Tiras, Stormwind). WL's `Loc.Format` used
`string.Replace`, which in the Lua build treats `%` in the replacement as a pattern character, so a power text
with "35%" crashed the quest reward before it handed over units. Upstream: #4061 added a safe replacement, #4083
removed it (4.8.2 ships that), #4189 (5.0 beta, 253 files) restored it — not cherry-pickable alone, so the bot
brings the same small change in `Loc.cs` as its own commit.
